# 23. Flink metric jobs: repo-owned schemas, window-based conversion, savepoint restarts, unpartitioned Iceberg tables

Status: Accepted (2026-11-18)

## Context

Step 4 of M1 adds the Flink SQL jobs. Metric jobs read the six `shop.*` topics (ADR 0021) and write windowed metrics to Kafka topics. A separate materialization job copies event and metric topics into Iceberg (ADR 0018). The step is done when Flink's metrics equal the generator's ground truth exactly, window by window, on a backfill. Five choices shape the jobs:

- **Metric schemas.** Metric topics need Avro key and value schemas in Schema Registry, like the events (ADR 0020). Flink's `avro-confluent` format can derive one from the table's columns, or be given one through its `avro-confluent.schema` option.
- **Conversion.** An order follows its checkout by about 15 seconds to 3 minutes, so a customer's checkout and order often fall in different 5-minute windows.
- **Abandonment.** The ground truth counts sessions abandoned after a failed payment from a flag that is never serialized. From the events alone, Flink can only infer abandonment after a timeout: a failure followed by no retry and no order.
- **Restarts.** A Flink job's progress has two parts: its Kafka offsets and the state of open windows. Kafka's committed consumer offsets hold only the first. Checkpoints (periodic) and savepoints (taken on a deliberate stop) hold both.
- **Iceberg layout.** Volumes are small (about 9,000 events per hour). The Iceberg sink commits files at every checkpoint, every 10 seconds (set in step 2).

## Options considered

Metric schemas:
- Generated by Flink from the SQL columns: nothing to maintain, but a generic record name, no field docs, every column without `NOT NULL` a nullable union, and a SQL change silently registers a new schema version (or fails at runtime on a compatibility error)
- `.avsc` files in the repo, registered by us and passed to Flink: each metric is described in SQL and in Avro, and Flink refuses to start when they disagree

Conversion:
- Per window: orders placed in the window ÷ checkouts started in the window. Two counts, no join, final when the watermark passes the window end; smooths and slightly delays changes, can exceed 1
- Per checkout cohort: the share of checkouts started in the window that became orders. Sharp and bounded by 1, but needs an interval join on `session_id` with a time bound, and each window is final only after the bound

Abandonment:
- Computed in Flink with a session timeout, the ground truth changed to the same rule
- Kept in the ground truth only

Restarts:
- Resume from committed consumer offsets: simple, but the window open at the stop is published with partial counts
- Stop with a savepoint and resume from it; periodic checkpoints cover crashes
- Always reprocess from the earliest offset: correct, but append-only metric topics (ADR 0018) would then hold every window again after each restart

Iceberg layout:
- Partitioned by `days(event_time)`
- Unpartitioned
- With or without Kafka metadata columns

## Decision

**Metric topics and schemas.** Three topics, `metrics.orders_1m`, `metrics.checkout_funnel_5m` and `metrics.payments_by_provider_5m`, append-only like the event topics. Their key and value schemas are `.avsc` files in the repo, with docs on every field, registered under `<topic>-key` and `<topic>-value` before the jobs start, and passed to Flink through `avro-confluent.schema`. The key is the row's identity: `window_start`, plus `provider` for payments. Value fields follow the ground-truth records.

**Conversion** is per window: `orders_placed / checkouts_started` over the same 5-minute tumbling window, as the ground truth computes it. Cohort conversion is later work.

**Abandonment** stays in the ground truth only, as an answer key for evaluating the agent's explanations. Flink's funnel metric does not include it. Computing it in Flink is later work, together with cohort conversion, since both need a session join with a timeout.

**Restarts** use Flink's own state handling:
- Checkpoints and savepoints are stored in RustFS (bucket `flink`), through the S3 file system plugin that ships with the Flink image.
- `make jobs-stop` stops each job with a savepoint; `make jobs` resumes each job from its latest savepoint, or reads its topics from the earliest offset when it has none.
- The Kafka sink is at-least-once. After a crash, a job resumes from its last checkpoint and may write some windows again. Consumers treat the key as the identity of a row, so a repeated window replaces the earlier one. Exactly-once (Kafka transactions, consumers reading committed only) is not needed at this stage.

**Iceberg tables** in `lake.shop.*` and `lake.metrics.*` are unpartitioned and have three extra columns, `kafka_partition`, `kafka_offset` and `kafka_timestamp`, alongside the value's fields. They are copied as metadata and do not count as logic under ADR 0018's pure-copy rule. Compacting small files is later work.

## Consequences

+ Metric topics have reviewed contracts with documented fields, the same as events, ready to be described as data products in M2 (ADR 0007)
+ Per-window counts are simple to compute and to check exactly against the ground truth
+ Windows stay exact across a deliberate stop and restart; a crash can only repeat whole windows, never publish partial ones
+ Every row in the lake can be traced to its Kafka record; `(kafka_partition, kafka_offset)` makes any duplicate copy visible
+ Partitioning can be added later through Iceberg partition evolution, without rewriting data
- Each metric is described twice, in SQL and in Avro
- Window-based conversion lags and blurs sudden changes; the agent's explanation must not read it as cohort conversion
- The agent cannot see abandonment directly in M1, only failure rates and conversion
- The job runner must track savepoints, and consumers must tolerate a repeated window after a crash
- Tumbling windows emit no row for a window with no events, while the ground truth writes zero rows; the comparison treats a missing row as zero
- Many small Iceberg files (one per checkpoint) until compaction is added
